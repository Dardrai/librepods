## What's changed

- **Fixed Spatial Audio on supported Android phones.** A live switch in the
  AirPods settings controls Android's surround renderer for the selected
  Bluetooth device. Supported multichannel media is rendered to stereo before
  the existing AAC-ELD/PCM32 encoder. Ordinary stereo content keeps its existing
  path; this does not add a stereo upmixer.
- **Automatic capability and state loading.** The control checks the actual
  output and device settings. It requests root only from an explicit action
  and links to Android's sound settings if the system-wide renderer is off.
  Changing the setting does not reconnect Bluetooth or adjust volume.
- **Shared motion-stream ownership.** Head-motion consumers no longer stop
  each other's stream. Control-channel refresh preserves active consumers,
  while disconnects and returning both buds to the case release them.
- **Head-tracking groundwork.** Added bounded debug-only raw motion capture
  and standalone Android sensor diagnostics. Head-tracked spatial playback is
  not enabled yet: the Pro 3 motion axes and scale still need calibration.

## Validation

On the Pixel 10 Pro XL, silent and sequential-channel probes exercised Android's
six-channel spatial renderer with stereo PCM32 output, zero reported probe
underruns and unchanged media volume. Android also discovered the temporary
standard head-tracker sensor; the diagnostic removes it after use. The first
quiet listening comparison was too soft to judge the audible effect.

Regression coverage checks selected-device writes, root access, stale owners,
rollback, control refresh, shared motion ownership, debug capture limits and
the live settings interface. CI runs the full Android, lint and codec checks
before publishing signed APKs with the existing signing key. The repeated,
more audible channel comparison was confirmed to sound spatial by the listener.
