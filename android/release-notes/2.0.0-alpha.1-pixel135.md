## What's changed

- **Keep the working spatial-audio control.** Fixed Spatial Audio loads through
  the existing root grant and switches the selected AirPods off and on without
  undoing the choice. The Pixel134 on-device check confirmed both native states
  and unchanged volume.
- **Prepare real head-tracking tests.** An explicit, foreground DEBUG diagnostic
  now connects the existing Pro3 motion stream to Android's standard head-tracker
  interface. It calibrates the current bud's axes from a short guided movement;
  it never guesses the side from a model number or reuses another connection's
  calibration.
- **Stop cleanly when conditions change.** The diagnostic has a short deadline,
  stops on connection or primary-bud changes and restores the starting
  head-tracking preference. Closing its screen or reconnecting the app service
  cannot silently restart it. A slow app callback cannot hold its sensor open.
- **Check the native interface in CI.** Both Linux and Android header-layout
  checks now run alongside pose-math, permission, ownership and cleanup tests.

Head tracking is still a controlled diagnostic, not a new public listening mode.
Real-motion renderer delivery and listening validation are required before
enabling it in the normal interface. Fixed spatial audio applies to supported
multichannel media; ordinary stereo playback remains unchanged.

This update changes no AAC-ELD encoder, PCM32 route, Bluetooth identity, volume
curve, Game Mode or audio buffers. The normal signed builds retain the complete
AAC-ELD/PCM32 payload and existing signing certificate.

## Validation

Tests cover calibrated axes and sign, sensor-clock continuity, delayed gravity
during calibration, malformed/stale poses, native HID controls, root ownership,
blocked callbacks, cancellation, role changes and preference restoration.
CI also runs the existing native audio sanitizer, decoded AAC-ELD quality,
Android lint and full signed-package checks before publishing.
