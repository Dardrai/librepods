## What's changed

- **Restore head tracking after reconnecting.** The same AirPods Pro 3 pair can
  report a different model number after connecting again. The old lookup treated
  A3063 and A3064 as different products and rejected an otherwise valid saved
  calibration, leaving Head Tracking on with no sensor provider. Lookup now uses
  the existing Pro 3 model family while still requiring the exact pair address,
  full bud-role report, firmware and profile format.
- **Keep existing calibrations.** Valid profiles saved under the older model
  numbers remain readable. Matching duplicates are accepted; conflicting bases
  require calibration. A new save replaces only that exact source's old aliases.
  Corrupt newer data cannot silently resurrect an older calibration, and stored
  profiles never restore an old sensor clock.
- **Keep startup identity stable.** A known Pro 3 model alias changing during
  setup or streaming no longer changes the source identity. Bud-role, firmware,
  transport and device changes retain their existing guards. Cached diagnostics
  now include calibration readiness and provider availability.

The 5 ms / 200 Hz request and safe fallback from Pixel138 remain in the DEBUG
head-tracking preview. No AAC-ELD encoder, PCM32 format, volume curve, audio buffer,
call route or Bluetooth connection setting is changed. Dolby Atmos work is separate.

## Validation

Read-only inspection on the Pixel confirmed the blocked state: root access and
the native head-tracking preference were present, but the current model was A3063
and valid saved profiles used A3064. Replaying the latest recorded calibration
with its exact saved basis produced 641 valid poses from 642 samples, with no
converter failure and an exact match to recalibration from the recorded phases.

Regression coverage includes legacy model aliases, full source identity,
conflicting profiles, scoped replacement, corrupt canonical data, normal provider
startup and calibration ownership. CI runs Android tests and lint, native audio
checks, and complete signed AAC-ELD/PCM32 packaging verification.

Actual 200 Hz delivery, live provider recovery and acoustic motion-to-sound
latency still require a listening check with the buds connected.
