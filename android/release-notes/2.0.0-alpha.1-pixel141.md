## What's changed

- **Remove repeated state work from motion delivery.** Each sensor report still
  reaches motion consumers, but an already-active stream no longer rebuilds the
  full device state to announce Active again. Actual state transitions and resets
  keep their existing behavior.
- **Locate head-tracking delivery gaps.** Small, constant-space counters separate
  time spent waiting for Bluetooth reads, packet processing, sensor-parser locks,
  publication and app collection. Device-clock intervals and counter steps are
  measured before the latest-value flow can combine reports. The largest HID
  submission gap records its host time and original source timestamps, allowing
  comparison with Android's own tracking timeout. These are numeric diagnostics,
  with no packet logging, pose history or recordings.

This build preserves the Pixel140 quaternion fix, saved calibrations, native
spatial preferences, AAC-ELD/PCM32, codec buffers, volume and call routing. It does
not change sensor-rate requests, prediction limits or Android's native renderer.

## What the listening checks established

Pixel140 accepted turns that previously stopped its converter. A native 5.1
reference still reproduced a real delivery interruption: Android briefly changed
from world-relative tracking to static rendering when head data was 132 ms old,
then recovered about 170 ms later. A second run at the existing fallback sensor
rate stayed active, but audible movement steps remained. Neither run reported an
audio underrun.

The new counters are intended to locate that remaining interruption rather than
hide it by extending prediction or treating old sensor data as fresh. Smoothness,
sustained 200 Hz delivery and acoustic latency remain unverified. Native head
tracking remains a DEBUG preview; Tidal's already-binaural Dolby path requires its
separate renderer integration.
